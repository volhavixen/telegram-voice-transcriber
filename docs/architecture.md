# Архитектура и эксплуатация

## Где работает бот

Рабочий экземпляр находится на Ubuntu 24.04 VPS (`199.68.199.130`). Служба
`telegram-voice-transcriber.service` запускается через `systemd` при старте
сервера и перезапускается после сбоя. Бот опрашивает Telegram методом long
polling. Компьютер разработчика в обработке сообщений не участвует.

GitHub хранит исходный код, тесты и workflow. GitHub Actions выполняет тесты
при push и pull request. После успешных тестов push в `main` запускает
обновление VPS по SSH. GitHub Actions не служит постоянно работающим хостом:
его задача здесь — проверка и доставка кода.

## Путь сообщения

1. Пользователь отправляет голосовое или аудио в Telegram.
2. Бот получает обновление через Bot API и проверяет Telegram user ID,
   длительность, размер и формат файла.
3. Бот скачивает аудио во временный файл VPS и ставит задание в очередь.
4. Один рабочий процесс последовательно расшифровывает задания моделью
   `faster-whisper base` на CPU в режиме `int8`.
5. Бот отправляет текст через Bot API. Временный файл удаляется после обработки.

Модель загружается с Hugging Face при первой установке и хранится в
`/var/lib/telegram-voice-transcriber/huggingface`. В репозиторий она не входит.
Код и виртуальное окружение находятся в `/opt/telegram-voice-transcriber`.
Токен бота и список разрешённых пользователей хранятся только в `.env` на
VPS; GitHub Actions не передаёт этот файл и не содержит токена Telegram.

## Ресурсы и стоимость

VPS: 1 vCPU, 1 ГБ RAM, 10 ГБ диска, 512 МБ swap. На нём также работают
другие службы, поэтому запас памяти ограничен. `base` с `int8` и
`WHISPER_BEAM_SIZE=1` выбран после проверки реального голосового сообщения:
`tiny` ошибалась чаще, а `beam_size=5` исказил отрицание. Более крупную модель
на этом VPS не включаем без замеров и запаса памяти.

Платных токенов API в рабочем пути **0**: Whisper работает на VPS без вызова
OpenAI или другого платного сервиса. Telegram также не тарифицирует слова
расшифровки как токены LLM. Цена работы — аренда VPS, трафик и электричество
провайдера. Сокращение текста расшифровки втрое означало бы потерю содержания,
поэтому бот возвращает сказанное полностью. Расход токенов Codex относится к
разработке и не меняется от работы бота; обещать его сокращение втрое через
изменения Python-кода нельзя.

## Обновления и проверки

`push main` → тесты на Linux, macOS и Windows → SSH-доставка `bot.py`,
зависимостей и файлов развёртывания → установка зависимостей → перезапуск
службы → проверка `systemctl is-active`.

Проверка на VPS:

```bash
systemctl status telegram-voice-transcriber.service --no-pager
journalctl -u telegram-voice-transcriber.service -n 100 --no-pager
free -h
```

Тесты проекта:

```bash
python -m unittest discover -s tests -q
```

Для ручного локального теста остановите службу на VPS на время запуска,
поскольку Telegram должен иметь один активный опрос с данным токеном.

## Ограничения

- Расшифровка может ошибаться в именах, редких выражениях и отрицаниях;
  важные фразы нужно сверять с аудио.
- Без `API_ID` и `API_HASH` Telegram Bot API не отдаёт ботам файлы более
  20 МБ. Поддержка MTProto реализована, но на текущем VPS не включена.
- При недоступности VPS бот не отвечает до восстановления службы или сервера.
- Очередь находится в памяти процесса: задания в ней не переживают перезапуск.
